# セキュリティモデル

この文書は、`kitty_ja` とインストーラーが想定する脅威と、それに対する制限の実装をまとめたものである。

- 記述は、リポジトリのコードを読んで確かめた内容に限る。コードから確かめられないことは、その旨を書き、6 章にまとめる。
- 「〜のコメント」と書いたものは、その理由や前提がソースコード中のコメントに書かれていることを示す。
- 全体の構成は [ARCHITECTURE.md](ARCHITECTURE.md) にある。

## 1. 範囲と前提

**対象**: `kitty_ja\`、`.wezterm.lua`、`install.ps1`・`install.cmd`、`uninstall.ps1`・`uninstall.cmd`、`tools\New-Package.ps1`

**信頼するもの**（この設定の中では守らない）

- WezTerm、PowerShell、Windows の本体
- 利用者本人のキー操作
- 利用者と同じ権限で動くローカルのプログラム。設定ファイル・データファイル・環境変数を書き換えられるので、この設定の中の対策では防げない。

**信頼しないもの**（入力として疑う）

- 端末に出力される文字列。ssh 先のホスト、`cat` などで表示したファイル、実行したプログラムの出力は、画面の文字だけでなく、制御用の文字列（エスケープシーケンス（escape sequence））も自由に出せる。WezTerm はこれを解釈して、タイトル、現在のフォルダ、ユーザー変数（user variable）などを変える。
- 画面の文字列から利用者が選んだもの（ヒント（hints）で選んだ文字列、マウスの選択範囲）。選ぶ操作は利用者のものだが、中身は端末の出力に由来する。

## 2. 守るもの

| 守るもの | 損なわれる例 |
|---|---|
| 意図しないプログラムが実行されないこと | 画面に出た実行ファイルのパスを Windows の「開く」に渡して、実行してしまう |
| ネットワークの相手へ勝手に接続しないこと | ネットワークのパス（`\\server\share`）を開こうとして相手へ接続する。コードのコメントでは、接続して認証情報を送りうる、としている（`panes.lua`、`tab_memory.lua`） |
| 外部プログラムへ意図しない引数が渡らないこと | 画面の文字列が、エディタのオプションとして解釈される |
| 利用者の既存の設定とデータが失われないこと | インストールで既存の `.wezterm.lua` を上書きする、リンク先のフォルダの中身を消す、壊れた記憶ファイルを上書きする |
| 配布物に作者の個人情報が入らないこと | 作者のホームのパスやメールアドレスが、公開する zip に入る |

## 3. 脅威と経路

| 経路 | 攻撃する側ができること | 対策しないと起きること | 制限 |
|---|---|---|---|
| フォルダの通知（OSC 1337 のユーザー変数 `kitty_ja_cwd`、OSC 7） | シェル連携と同じ形の通知を端末に出す | タブ記憶が別のフォルダの名前・色を付ける。タブ構成の保存にそのフォルダが入り、次回の起動でそこにシェルが開く。ネットワークのパスなら起動のたびに接続する | 4.1、4.2 |
| タブ構成の復元 | ネットワークのパスを保存させる（通知の偽装、または利用者が実際にそこにいた） | 起動のたびに自動で接続する | 4.2 |
| 画面の文字列を開く操作 | 実行形式のパスやネットワークのパスを画面に出し、利用者に選ばせる | 選んで開いただけで、実行・接続される | 4.3 |
| 画面の「ファイル:行番号」をエディタで開く操作 | オプションに見える文字列や、ネットワークのパスを画面に出す | エディタに意図しない引数が渡る。接続する | 4.4 |
| インストーラー | （配布物の改ざんは 4.5 の「防げないこと」） | 既存の設定やリンク先を消す。意図せずソフトを入れる、権限を上げる | 4.5 |
| 配布物の作成 | — | 個人のパスやメールアドレスが公開される | 5 |

## 4. 制限ごとの内容

### 4.1 合言葉つきのフォルダ通知

**防ぐもの**: 端末に文字を出すだけのもの（ssh 先や表示したファイル）が、シェル連携のフォルダの通知（ユーザー変数 `kitty_ja_cwd`）を偽装すること（`state.lua`、`integration.ps1` のコメント）。

**実装**

| 段階 | ファイル・関数 | 内容 |
|---|---|---|
| 生成 | `state.lua` の `shell_token` | `math.random(0, 0xFFFFFFFF)` を 4 回呼び、8 桁の 16 進数を 4 つつないだ 32 文字の合言葉（token）を作る。WezTerm のプロセスごとに 1 個作り、`wezterm.GLOBAL` に置く（設定の再読み込みでは変わらない） |
| 受け渡し | `shell.lua` の `apply` | 環境変数 `KITTY_JA_TOKEN` に入れ、`set_environment_variables` でシェルへ渡す |
| シェル側 | `integration.ps1` | 読んだら `$global:KittyJaToken` へ移し、`Remove-Item -LiteralPath Env:KITTY_JA_TOKEN` で環境変数から消す（子プロセスへ渡さないため） |
| 通知 | `integration.ps1` の `Send-KittyJaLocation` | 「合言葉、縦線、パス」を UTF-8 で Base64 にし、OSC 1337 の `SetUserVar=kitty_ja_cwd=...` で送る |
| 検証 | `tab_memory.lua` の `notified_cwd` | 値の長さが上限（`MAX_PATH_LENGTH` + 64 バイト）以下で、先頭の合言葉が一致し、正規化したパスが 4096 バイト以下で制御文字を含まないときだけ使う。それ以外は偽装とみなして無視する |
| 回復 | `integration.ps1` の `prompt` | プロンプトのたびに、正しい通知を出し直す |

**防げないこと**

- **OSC 7 は合言葉なしで使われる**: `tab_memory.pane_cwd` は、合言葉の合うユーザー変数が無いとき、WezTerm の `get_current_working_dir`（OSC 7 か、シェルのプロセスから WezTerm が調べたフォルダ）を使う（`reported_cwd`）。OSC 7 は端末に文字を出すだけで送れる。ここではドライブ文字で始まるパスだけを受け付ける（`is_local_path`）。
  - そのため、端末の中のプログラムが、合言葉の合わない値で `kitty_ja_cwd` を書き換えたうえで OSC 7 を送ると、ペインの現在のフォルダを、この PC の別のフォルダに見せかけられる。
  - 次のプロンプトで正しい値に戻るが、ssh の接続中のように、ローカルのシェルのプロンプトが出ない間は続く。
  - その間に起きうるのは、タブ名・色がそのフォルダの記憶に変わること、タブ構成の保存にそのフォルダが入ること、ヒントで選んだ相対パスがそのフォルダを基準に解決されること、である。どれもドライブ文字で始まるパスに限られ、4.2〜4.4 の検査はそのまま効く。
- **擬似乱数**: 合言葉は Lua の `math.random`（擬似乱数（pseudo-random number））で作る。暗号論的に安全な乱数ではない。乱数の種（seed）を与える処理はこのリポジトリのコードには無く、WezTerm の Lua 実行環境がどう与えるかは確認できない。
- **同じシェルの中のスクリプト**: 合言葉は `$global:KittyJaToken` として pwsh のセッションに残るので、そのセッションで実行したスクリプトは読める。
- **環境変数が残る場合**: 環境変数から合言葉を消すのは `integration.ps1` だけである。`TERM_PROGRAM` が `WezTerm` でないときは、消す前に終わる。`integration.ps1` を通らずに起動されたプログラムに WezTerm がこの環境変数を渡した場合も、消されない。WezTerm がどのプログラムに `set_environment_variables` を渡すかは、このリポジトリのコードからは確認できない。
- **合言葉が合えばネットワークのパスも受け付ける**: `notified_cwd` は `is_local_path` を使わない。ネットワークのパスを保存したり開いたりする側で、4.2〜4.4 の検査が別に止める。タブ記憶（`tab_memory.lua`）はパスを文字列として照合するだけで、そのフォルダにはアクセスしない。

### 4.2 タブ復元のパス制限

**防ぐもの**: 起動のたびに、保存されたネットワークのパスへ自動で接続すること（`session.lua`、`tab_memory.lua` のコメント）。

**実装**

- **パスの検査**（`tab_memory.lua` の `is_local_path`）: 文字列で、4096 バイト以下、`^%a:\\` に合い（ドライブ文字、コロン、`\` で始まる）、制御文字を含まないものだけを通す。コメントでは、ネットワークのパス（`\\server\share`）やデバイスのパスは開こうとするだけで相手へ接続して認証情報を送りうるので、自動で開く処理（セッションの復元、ヒント）はこの検査を通ったパスだけを使う、としている。
- **保存時**（`session.lua` の `pane_cwd_for_save`）: ペインの現在のフォルダが検査を通らなければ保存せず、そのペインで最後に分かっていた、検査を通ったフォルダを使う。無ければフォルダを持たない葉になる。
- **復元時**（`session.lua` の `leaf_cwd`）: `session.json` の各葉のフォルダを正規化し、検査を通らなければ、存在の確認もせずホームで開く。
- **存在の確認**（`probe_dirs`、`resolve_cwd`）: 検査を通ったフォルダも、`settings.session_probe_timeout_ms`（既定 2000 ミリ秒）以内に `wezterm.read_dir` が成功したものだけを使う。それ以外はホームで開く。
- **プログラムは起動しない**: 復元で起動するのは既定のシェルだけである。`session.json` にはコマンドを書く欄が無く、`spawn_tab`・`spawn_window`・`split` に渡すのはフォルダと大きさだけなので、ファイルの中身からプログラムが起動されることはない。
- **ほかの値も型を確かめる**: 色は `#RRGGBB` の形だけ（`tab_memory.lua` の `normalize_color`）、タブ名は文字列だけ、大きさは `tonumber` で数値にできたものだけ、分割の向きは `Right` か `Bottom` だけを使う。

**防げないこと**

- **ネットワークドライブ**: 検査はパスの形だけを見るので、ネットワークの共有をドライブ文字に割り当てたもの（ネットワークドライブ）は通る。起動時の存在の確認でアクセスし、届けばそこでシェルを開く。`probe_dirs` のコメントでも、切断中のネットワークドライブを時間切れの例に挙げている。
- **時間切れの後の確認**: 時間切れの後、予約した `wezterm.read_dir` の呼び出しが中断されるかは、このリポジトリのコードからは確認できない。コードは、時間切れの時点の結果を写して使い、後から届いた結果を混ぜない。
- `session.json` を書き換えられる同じ権限のプログラムは、範囲外である（1 章）。

### 4.3 画面のパスを開く操作の制限

**防ぐもの**: 画面の文字列を Windows の「開く」に渡して、実行形式が実行されること、ネットワークのパスへ接続すること（`panes.lua` のコメント）。

**対象の操作**

| 操作 | キー | 関数 | 開くもの |
|---|---|---|---|
| 選択内容を外部プログラムへ渡す | Ctrl+Shift+O | `pass_selection_to_program` | http(s) の URL、またはパス |
| パスを開く | Ctrl+Shift+P → Shift+F | `hint_open_path` | パスだけ |
| 画面上の URL を選んで開く | パレットから（Ctrl+Shift+E は `.wezterm.lua` が別の操作に差し替える） | `hint_open_url` | http(s) の URL だけ |

どれも、利用者が文字列を選ぶ操作（マウスの選択、またはヒントの選択（QuickSelect））を経る。画面に出ただけで開くことはない。

**実装**

1. **URL**（`is_web_url`）: 全体が `^https?://[^%s%c]+$` に合うもの（空白と制御文字を含まない http / https の URL）だけを `wezterm.open_with` に渡す。
2. **パスの解決**（`resolve_path`）:
   - `~` で始まればホームに置き換える。ドライブ文字か、`\\` または `//` で始まれば絶対パスとしてそのまま使う。それ以外は相対パスとして、ペインの現在のフォルダ（`tab_memory.pane_cwd`）を前に付ける。フォルダが分からなければ開かない。
   - 正規化（`tab_memory.normalize_path`）した後、`tab_memory.is_local_path` を通らなければ開かない。ネットワークのパスとデバイスのパスはここで除かれる。
   - ドライブ文字より後ろに `:`（代替データストリーム（alternate data stream））、`*`・`?`（ワイルドカード）、`"`・`<`・`>`・縦線を含むものは開かない。
3. **開く前の確認**（`open_local_path`）:
   - フォルダ（`wezterm.read_dir` が成功するもの）なら開く。
   - ファイルは、拡張子があり、実行形式の一覧に無く、読み取りで開ける（実在する）ものだけを開く（`is_readable_file`）。
   - 拡張子の無い名前は開かない。コメントでは、Windows が `.exe` などを補って実行することがあるため、としている。
   - 実行形式の一覧は、`EXECUTABLE_EXTENSIONS` の 44 種（`exe`、`bat`、`cmd`、`com`、`lnk`、`url`、`ps1`、`msi`、`js`、`vbs`、`hta`、`scr`、`reg`、`py` など）に、環境変数 `PATHEXT` の拡張子を足したもの（`executable_extension_set`）。大文字・小文字は区別しない。
   - 開かなかったときは、理由をログに書く。

**防げないこと**

- **拒否リスト（denylist）である**: 一覧にも `PATHEXT` にも無い拡張子のファイルは開く。例えば `.html`、`.docm`、`.iso` は一覧に無い（`PATHEXT` に含まれていなければ開く）。開いた後の動作は、その拡張子に関連付けられたプログラムと Windows の設定による。
- **URL の行き先**: http(s) の URL は、行き先を問わず開く。
- **ネットワークドライブ**: 4.2 と同じく、ドライブ文字のネットワークドライブは通る。
- **相対パスの基準**: 相対パスは、ペインの現在のフォルダを基準にする。4.1 のとおり、それが偽の OSC 7 で別のローカルのフォルダになっていると、そのフォルダの中のファイルが対象になる（上の検査はそのまま効く）。
- **`wezterm.open_with` の動作**: Windows でどの仕組みを使って開くかは、このリポジトリのコードからは確認できない。

### 4.4 ファイルの行を開く操作の制限

**防ぐもの**: 画面の「ファイル:行番号」をエディタに渡すとき、ネットワークのパスや、オプションに見える文字列がエディタの引数になること（`panes.lua` のコメント）。

**実装**（`panes.lua` の `hint_open_line_number`。Ctrl+Shift+P → N）

1. ヒントで選んだ文字列を `^(.*):(%d+)$` で、パスと、数字だけの行番号に分ける。
2. パスは 4.3 と同じ `resolve_path` で、この PC のドライブのパスに直す。直せなければ開かない。
3. 読み取りで開けない（実在しない）ファイルは開かない（`is_readable_file`）。
4. コマンドは引数の配列で組み立てる。`settings.editor_command`（Program Files に Notepad++ があればそれ、無ければ `%SystemRoot%\System32` のメモ帳のフルパス）、パス、`settings.editor_line_option`（Notepad++ のときだけ `-n`）に行番号をつないだもの、の順である。これを `wezterm.background_child_process` に渡す。コマンドの文字列は組み立てない。
5. パスはドライブ文字で始まるので、`-` や `/` で始まるオプションの形にはならない。

**防げないこと**

- 実行形式かどうかは見ない。エディタで開くだけで、その後の動作はエディタによる。
- ネットワークドライブは通る（4.2 と同じ）。
- 引数の配列がどのようにエディタのコマンドラインになるかは WezTerm の実装により、このリポジトリのコードからは確認できない。

### 4.5 インストーラーの方針

**防ぐもの**: 利用者の既存の設定とリンク先の消失、意図しないソフトの導入や権限の昇格、PC の設定の変更。

**実装**

| 方針 | 実装 |
|---|---|
| 既定ではダウンロードしない | `install.ps1` がソフトを入れるのは、winget を呼ぶときだけである。winget を呼ぶのは、`-InstallMissing` を付けたときか、対話的な実行で確認に「はい」と答えたとき（既定は「いいえ」、`Confirm-Choice`）だけ。それ以外は入れ方を表示して止まる。winget のほかに、`install.ps1` がネットワークからダウンロードする処理は無い |
| 管理者権限を要求しない | `install.ps1` に、管理者として実行し直す処理は無い。設定のために書き込むのは `-HomePath`（既定は現在のユーザーのホーム）の下だけである（`-Link` のときは、リンク元のファイルの印も外す）。winget のインストーラーは管理者権限の確認を出すことがある（`install.ps1` の説明と確認の文言） |
| PC の設定を変えない | レジストリは WezTerm の場所を探すために読むだけ（`Find-WezTerm`）。環境変数と実行ポリシー（execution policy）は変えず、必要なら設定のしかたを表示する（`Get-PersistentExecutionPolicy` の後の警告） |
| 既存のファイルを残す | `Backup-ExistingItem`: 実体は名前に `.bak-<日時>` を付けて残す。リンク（ジャンクション（junction）・シンボリックリンク（symbolic link））はリンクだけを消し、リンク先には触らない。フォルダのリンクは `[System.IO.Directory]::Delete` を再帰の指定なしで呼ぶ。同じ中身なら何もしない（`Test-SameDirectoryContent`、`Get-FileSha256`）。`colors.txt` は無いときだけ置く |
| 変更の前に止まる | 配布物が足りない、ホームが無い、`<ホーム>\.config\wezterm\wezterm.lua` がある、`XDG_CONFIG_HOME` が設定されている、必要なソフトが無い（入れなかった）ときは、何も変更せずに止まる |
| 予定だけを見られる | `SupportsShouldProcess` で `-WhatIf` に対応する |
| 実行ポリシーはその回だけ迂回する | `install.cmd` は `-ExecutionPolicy Bypass` で `install.ps1` を実行する。この指定はその 1 回の実行だけに効く（ファイル内のコメント）。Windows PowerShell は `%SystemRoot%\System32` 以下のフルパスで指定する |
| アンインストールでも消さない | `uninstall.ps1` の `Remove-InstalledItem`: 実体は名前に `.removed-<日時>` を付けて残し、リンクはリンクだけを消す。入口は `kitty_ja` を読み込むものだけを対象にする。データは残す |

**防げないこと**

- **配布物そのものの正しさ**: `install.ps1` は、zip や自分自身が改ざんされていないかを確かめない（署名やハッシュの検証は無い）。`install.cmd` は実行ポリシーを迂回して `install.ps1` を実行し、`install.ps1` は置いたファイルから、インターネットから入手した印（Mark of the Web）を外す（`Unblock-File`）。印を外すのは、付いたままだと PowerShell の既定の設定（RemoteSigned）で `integration.ps1` を実行できないためである。入手した zip が正しいかは、利用者が `New-Package.ps1` の出力した SHA-256 と比べて確かめる必要がある。zip と同じ場所から SHA-256 を入手した場合、両方を差し替えられると検出できない。
- **見つけたプログラムを実行する**: `install.ps1` は、見つけた `wezterm.exe`（`--version` と `show-keys`）と `pwsh.exe`（実行ポリシーの確認）を実行し、確認に応じて `wezterm-gui.exe` を起動する。`wezterm.exe` と `pwsh.exe` は PATH からも探すので、PATH の前の方にある同名のプログラムが実行されうる（それを置けるのは同じ権限のプログラムで、範囲外）。
- **winget**: 入れるパッケージは ID（`Microsoft.PowerShell`、`wez.wezterm`）と `--exact --source winget` で指定し、`--accept-package-agreements --accept-source-agreements` で同意する。パッケージの中身の検証は winget に任せる。
- **バックアップは溜まる**: `.bak-<日時>` と `.removed-<日時>` は、自動では消さない。

### 4.6 そのほかの対策

- **Windows 付属のプログラムのフルパス**（`settings.lua`）: メモ帳と Windows PowerShell（PowerShell 7 が無いときのシェル）は、`%SystemRoot%\System32` 以下のフルパスで起動する。名前だけだと、カレントフォルダや PATH にある同名の別のプログラムが起動しうるため（`settings.lua` のコメント）。`SystemRoot` が無いときは `C:\Windows` を使う。
- **スクリプトのパスをコマンドの文字列に埋め込まない**（`shell.lua`）: `integration.ps1` のパスは環境変数 `KITTY_JA_INTEGRATION` で渡し、`-Command` には固定の文字列 `& $env:KITTY_JA_INTEGRATION` だけを書く。
- **壊れたデータを上書きしない**: `memory.json` を読めないときは保存しない（`tab_memory.lua` の `load_folders`、`remember`）。タブを 1 枚も復元できなかったプロセスは、`session.json` を上書きしない（`session.lua` の `restore_session`）。
- **別の WezTerm のデータに触らない**: `session.json` の持ち主が別に動いているとき、そのプロセスは復元も保存もしない（`session.lua` の `decide_role`）。
- **colors.txt の検査**: 色は `#RRGGBB` か `NONE`、キーは 1 桁の数字か、`^[%w_+%-.,<>/]+$` に合う指定だけを受け付ける（`tab_colors.lua` の `normalize_color`、`normalize_key`）。合わない行は読み飛ばす。

### 4.7 対策していないもの

- **スクロール履歴のファイル**: `.wezterm.lua` の Ctrl+Shift+E は、画面とスクロール履歴（scrollback）を `%TEMP%` の `wezterm-history-<日時>-pane-<ペイン番号>.txt` に書き、Notepad++ で開く。コードには、このファイルを消す処理が無い。端末に表示した秘密の文字列もそのまま残る。
- **データファイルは平文**: `memory.json`（フォルダのパスとタブ名）と `session.json`（フォルダのパス、タブ名、プロセス番号）は暗号化しない。アクセス権はコードでは設定しないので、置き場所のフォルダの設定による。
- **ログ**: 開かなかったパスなど、画面に由来する文字列を WezTerm のログに書く（`panes.lua` の `log`）。

## 5. 配布物の検査（New-Package.ps1）

zip にする前に、`dist\` に写したファイルを検査する。1 件でも見つかれば警告を出し、zip を作らずに止まる。

1. **入れるファイルを一覧で決める**: 許可リスト（allowlist）の方式である。トップレベルの決まったファイル（`$TopLevelFiles`）と、決まったフォルダ（`$Directories`）の中のファイルだけを写す。git の履歴や、一覧に無いファイルは入らない。
2. **ファイルの種類**: 拡張子が `.lua`、`.ps1`、`.cmd`、`.txt`、`.md` のどれかか、名前が `LICENSE` でなければ止まる。
3. **個人の情報らしき文字列**: 写したファイルを UTF-8 として読み、次のどれかに合う行があれば止まる（`$personalPatterns`。`Select-String` で検索するので、大文字・小文字を区別しない）。
   - 実行したユーザーのホームのパス
   - `Users` の下の、実行したユーザー名のフォルダ（`\` 区切りと `/` 区切り）
   - リポジトリの場所のパス
   - メールアドレスの形
   - ドライブ文字と `\` で始まる絶対パス。ただし `C:\Windows`、`C:\Program Files`、`C:\...`（省略の例）、`C:\no-such`（存在しないことを示す例）と、`HKLM:\` のようなレジストリのパスは除く
   - ネットワークのパス。ただし説明用の例の `\\server\share` は除く
4. **確認待ちの印**: 確認待ちを示す印（`$PendingMarkerPattern` に合う文字列）が残っていれば止まる。
5. **文字コード**: `install.ps1`・`uninstall.ps1` が BOM 付きでなければ止まる。BOM が無いと Windows PowerShell 5.1 で文字化けするため。
6. **改行**: `install.cmd`・`uninstall.cmd` の改行が CRLF でなければ止まる。

検査を通ると、zip と、その SHA-256 を書いた `<zip の名前>.sha256` を出力する。

**防げないこと**

- 検査は文字列の形で探すだけである。パスワードや API キーなど、上の形に当てはまらない秘密は検出しない。
- 実行したユーザー以外のユーザーのパスは、ドライブ文字と `\` で書かれていれば検出するが、`/` 区切りのものや、ドライブ文字の無いものは検出しない。
- コード署名はしない。SHA-256 は zip と同じ場所に出力する（4.5 の「防げないこと」）。
